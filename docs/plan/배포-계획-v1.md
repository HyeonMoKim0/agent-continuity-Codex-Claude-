# Agent Continuity 배포 계획 v1

## 0. 문서 상태

- 목적: 개인 도구인 Agent Continuity 를 다른 사람이 설치·사용할 수 있는 배포 형태로 전환한다.
- 전제: 연속성 계획서 v2 의 안전 원칙(fail-closed, 자동 병합 금지, 인증정보 미운반)은 배포 과정에서 약화되지 않는다.
- 상태: 초안 — 승인 후 D1 부터 구현.

## 1. 배포 대상과 지원 범위 선언

배포 전에 "누구를 위한 도구인가"를 먼저 고정한다.

| 항목 | v1 지원 | 비고 |
|---|---|---|
| 사용자 모델 | **1인 · 다기기** (개인 GitHub 계정, PC 2대 이상) | lease 가 단일 작성자 설계이므로 |
| 다중 사용자 공동 작업 | 미지원 (명시) | 팀이 같은 프로젝트를 공유하면 서로 작업권을 뺏는 경험이 됨 |
| OS | Windows 10/11 (UI 포함), Linux/macOS (CLI 스크립트만) | |
| 필수 외부 도구 | git 2.30+, PowerShell 7+, age (Phase 2 사용 시) | 설치 도우미 제공 |
| GitHub | 비공개 저장소 2개(프로젝트/vault) 생성 가능 계정 | Free 플랜 가능, branch protection 은 선택 |
| Phase 3 (세션 스냅숏) | 기본 비활성, 실험 기능 라벨 유지 | 버전 allowlist 절차 그대로 |

라이선스: MIT 권장 (age 등 의존 도구와 호환, 기여 받기 쉬움). 저장소 공개 전 결정 필요.

## 2. 현재 상태에서 배포를 막는 마찰 목록

실사용 온보딩(이 프로젝트 자체의 검증 과정)에서 실제로 겪은 것들:

1. PowerShell 7 미설치 / PATH 미반영 → 새 창 필요
2. ExecutionPolicy 로 스크립트 실행 차단
3. age 별도 설치 필요
4. vault·테스트 저장소를 사용자가 직접 만들어야 함
5. 명령이 길다 (여러 파라미터를 정확히 입력해야 Setup 가능)
6. `.exe` 가 아니라서 "실행 프로그램이 어디 있는지" 자체가 비직관적
7. 한국어 하드코딩 (영어 사용자 배제)
8. 업데이트 수단이 `git pull` 뿐
9. 코드 서명 없음 → SmartScreen/보안 경고 마찰 가능

## 3. 단계별 계획

### D1 — 패키징: "받아서 더블클릭이면 끝" (최우선)

- **PowerShell 모듈화**: `core/` + `adapters/` 를 `AgentContinuity` 모듈(.psd1 manifest, semver 버전)로 통합. launcher/bootstrap 은 모듈 함수를 호출하는 얇은 스크립트로 유지.
- **배포 채널 2개**:
  - GitHub Releases: 버전 태그마다 zip + `Install-AgentContinuity.ps1`(원클릭 설치: 압축 해제 → `%LOCALAPPDATA%\Programs\AgentContinuity` 배치 → 시작 메뉴/바탕화면 바로가기 생성).
  - PowerShell Gallery: `Install-Module AgentContinuity` (기업/차단 환경 대비 Releases 가 기본).
- **의존성 부트스트랩**: 설치 스크립트가 pwsh7/git/age 존재 검사 → 없으면 `winget install` 제안(동의 시 실행). ExecutionPolicy 는 바로가기가 항상 `-ExecutionPolicy Bypass` 로 우회(현행 유지)하고 설치 문서에 명시.
- **UI 실행 파일화(선택)**: 1차는 바로가기로 충분. 2차로 ps2exe 래핑 또는 소형 런처 exe 검토 — 코드 서명 없이는 SmartScreen 경고가 더 커질 수 있어 서명과 묶어서 결정.
- Go: 깨끗한 Windows VM 에서 "Release zip 다운로드 → 설치 스크립트 1회 → Setup 마법사 → 왕복 성공"이 문서만 보고 재현됨.

### D2 — 온보딩 마법사 강화

- Setup 을 **완전 대화형**으로: 파라미터 없이 실행하면 단계별 질문(기기 이름 → GitHub 인증 확인 → vault 자동 생성 제안(`gh` 있으면 `gh repo create --private`, 없으면 웹 안내) → 프로젝트 선택/승격 → agent 선택 → 아이콘/자동 시작).
- UI 에 "프로젝트 추가" 버튼: Setup 대화형 흐름을 UI 안에서 실행.
- `Test-AgentContinuity` 를 진단 리포트(복사·공유 가능한 텍스트)로 확장 — 이슈 제보 품질 확보.
- Quick Start 문서 한/영 + 트러블슈팅(2절의 마찰 목록 그대로 FAQ 화).
- Go: 신규 사용자가 파라미터를 하나도 몰라도 설정 완료 가능.

### D3 — 품질 기반: CI · i18n · 설정 외부화

- **GitHub Actions CI**: `windows-latest` + `ubuntu-latest` 에서 기존 42개 테스트 실행(age 설치 스텝 포함). Windows 레그가 생기면 CRLF·DPAPI·WPF 파싱 같은 Windows 전용 회귀를 자동으로 잡는다 — 이번에 수동으로 겪은 버그 2건이 정확히 이 부류.
- **i18n**: 사용자 노출 문자열을 ko/en 리소스 테이블로 분리, 시스템 로캘 기반 선택(기본 en, ko 완전 지원).
- **시크릿 스캔 규칙 외부화**: 규칙을 JSON 으로 분리해 사용자가 추가 가능(기본 규칙 삭제는 불가 — fail-closed 유지).
- profile/lease/transaction 의 `schemaVersion` 을 읽기 시점에 강제 검증(미래 버전 파일 → 안전 중단 + 업데이트 안내).
- Go: PR 마다 양 OS 테스트 green, 영어 로캘 스모크 통과.

### D4 — 업데이트와 릴리스 운영

- `Update-AgentContinuity`(또는 UI 버튼): 새 Release 확인 → 백업 후 교체 → 자가진단. 진행 중 lease 가 있으면 업데이트 거부(fail-closed).
- semver + CHANGELOG + 태그. vault 스키마 변경 시 마이너/메이저 규칙 문서화.
- 이슈/PR 템플릿, SECURITY.md(취약점 제보), 위협 모델 문서(vault 접근자는 lease·transaction 메타데이터 전부 열람 가능, 암호문은 수신자 키 없이 복호화 불가 등 — 계획서 §7.3/§14 요약).
- Go: 구버전 → 신버전 업데이트 왕복 시험 통과, 데이터 손실 0.

### D5 — 선택 확장 (수요 확인 후)

- 코드 서명 인증서 도입(비용 발생) → SmartScreen 마찰 제거, exe 패키징 재검토.
- winget 매니페스트 제출 (`winget install AgentContinuity`).
- macOS/Linux 용 트레이 UI (현재는 CLI 만).
- 팀(다중 사용자) 모드는 별도 설계 문서 없이는 착수하지 않음 — 단일 작성자 원칙과 충돌.

## 4. 구현 순서와 판단 기준

```
D1 패키징 → D2 온보딩 → D3 CI·i18n → D4 업데이트 → (수요 보고) D5
```

각 단계는 기존 원칙대로 Go 조건 충족 시에만 다음으로 넘어간다. 가장 먼저 만들 산출물은:

1. `AgentContinuity.psd1` 모듈 manifest + 모듈화 리팩터링 (기존 테스트 42개가 그대로 통과해야 함)
2. `Install-AgentContinuity.ps1` + GitHub Release 자동화(Actions)
3. 깨끗한 VM 설치 리허설 체크리스트

## 5. 위험

| 위험 | 통제 |
|---|---|
| 서명 없는 스크립트에 대한 보안 경고 | 문서 고지, D5 서명 도입 전까지 Releases 해시 공개 |
| 사용자 환경 다양성(한국어 외 로캘, 기업 프록시) | D3 i18n, CI 매트릭스, 진단 리포트 |
| 모듈화 리팩터링 중 회귀 | 기존 테스트 스위트를 게이트로 사용 (42/42 유지 조건) |
| 다중 사용자 오용 | README·Setup 에 1인·다기기 모델 명시, lease 충돌 화면에 안내 추가 |
